# Git Flow · 커밋 메시지

## 브랜치 (Git Flow)

| 브랜치 | 용도 |
|--------|------|
| `main` | 배포 가능한 프로덕션 이력 |
| `develop` | 다음 릴리스 통합 기본선 |
| `feature/<설명>` | `develop`에서 분기하는 기능 개발 (머지 후 브랜치 삭제) |
| `release/<버전>` | 릴리스 준비(버그픽스·메타만, 새 기능 금지) → `main`·`develop`에 반영 |
| `hotfix/<설명>` | `main` 긴급 수정 → `main`·`develop`에 반영 |

브랜치 이름은 영문·케밥케이스 등 기존 팀 관례를 따른다.

## 커밋 메시지 — 변경 요약은 **무조건 한국어**

- **제목(첫 줄)** 과 **본문(설명)** 에 들어가는 “무엇을·왜 바꿨는지” 요약은 **한국어로만** 쓴다.
- 다음은 한글 필수 범위 밖으로 둘 수 있다: 브랜치명, 이슈 키(`ABC-123`), 파일 경로, 심볼 이름, 버전 문자열.

선택적으로 첫 줄 앞에 Conventional Commits 형태 접두사를 붙일 수 있다. 접두사는 영문 유지, **그 뒤 설명 문구는 한국어**.

```text
feat: 받은 토마토 목록 새로고침 시 로딩 상태 표시

무한 스크롤 중 중복 요청을 막기 위해 진행 중 플래그를 추가했다.
```

```text
fix: 홈 숏컷 카드 탭 시 간헐적 크래시 수정

동시 탭 처리 시 해제된 뷰에 접근하던 레이스를 제거했다.
```

에이전트가 커밋 메시지를 작성할 때 위 규칙을 따르고, 사용자가 영문 요약만 요청해도 **요약 문구는 한국어로** 작성한다.
